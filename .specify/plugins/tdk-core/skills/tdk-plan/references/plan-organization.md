# Plan Organization

## Directory Layout

Generated by `setup-plan.ts` (Step 1):

```
.specify/specs/{task_id}/
├── spec.md
├── plan.md                              # entry point (≤ 80 lines)
├── research.md                          # Phase 0 output
├── data-model.md                        # Phase 1 output
├── contracts/                           # Phase 1 output
│   └── ...
├── quickstart.md                        # Phase 1 output
├── phases/                              # implementation phase files
│   ├── phase-01-{slug}.md
│   ├── phase-02-{slug}.md
│   └── phase-NN-unit-tests.md           # UT phase (auto-included if conditions met)
└── reports/                             # subagent outputs
    ├── researcher-NN-{topic}.md
    └── scout-NN-{area}.md
```

## plan.md Structure

Keep `plan.md` ≤ 80 lines, with these sections in order:

1. YAML frontmatter (see `output-standards.md` — reserves all fields).
2. `## Context` — links to spec, research, brainstorm, related plans.
3. `## Problem` — what we're solving (1–3 paragraphs).
4. `## Goal` — desired end state (1 paragraph).
5. `## Scope` — writable / read-only zones.
6. `## Phases` — 4-column table linking each `phases/phase-NN-*.md`.
7. `## Success Metrics` — measurable criteria.
8. `## Key Constraints` — non-negotiables.
9. `## Decisions Made` — table per `references/output-standards.md`.
10. `## Unresolved Questions` (if any).

## Phases Table (4-column convention)

```markdown
| # | File | Status | Blocks | BlockedBy |
|---|------|--------|--------|-----------|
| 00 | [phase-00-foo](phases/phase-00-foo.md) | todo | 01 | — |
| 01 | [phase-01-bar](phases/phase-01-bar.md) | todo | — | 00 |
```

**Status vocabulary:** `todo` → `in_progress` → `done` (also: `skipped`, `blocked`, `cancelled`). Update via `bun src/commands/util/update-phase-frontmatter-status.ts` (phase file frontmatter — REQUIRED) + `bun src/commands/util/update-phase-status.ts` (plan.md table).

**Blocks / BlockedBy:** comma-separated phase numbers (e.g., `01, 03`) or `—` if none.

## Phase File Conventions

Every `phases/phase-NN-*.md` MUST include (in order):

- YAML frontmatter (REQUIRED) with: `phase`, `title`, `status`, `priority`, `effort`, `dependencies`. Header-block alternative deprecated — tooling assumes frontmatter.
- `## Context Links` — links to brainstorm, research, target files.
- `## Overview` — what this phase does + why.
- `## Key Insights` — non-obvious findings from research.
- `## Requirements` — Functional + Non-functional checkboxes.
- `## Architecture` — component layout + data flow.
- `## Related Code Files` — Modify / Create / Delete lists.
- `## Implementation Steps` — numbered, actionable.
- `## Todo List` — checkbox mirror of steps.
- `## Success Criteria` — definition of done.
- `## Risk Assessment` — likelihood × impact × mitigation.
- `## Security Considerations` — auth, data, attack surface.
- `## Next Steps` — what this unblocks.
- `## Unresolved Questions` (or "None").

## Cross-Plan Awareness

See `references/cross-plan-deps.md` (Phase 05) for the bidirectional `blockedBy` / `blocks` scan. Until that phase ships, `blockedBy: []` and `blocks: []` are reserved fields with no auto-detection.

## File Naming

`phases/phase-NN-kebab-case-slug.md` — lowercase, hyphen-separated, descriptive. Enforced by F19 Lowercase Enforcement (see `handle-existing-plan.md`).
