# Plan Output Contract

Single source of truth for `/tdk-plan` generated artifact layout, `plan.md` schema, phase file conventions, and output quality rules.

## Directory Layout

Generated by `setup-plan.ts` in Step 1:

```text
.specify/specs/{task_id}/
├── spec.md
├── plan.md
├── research/
│   ├── yyMMdd-HHmmss-{slug}.md
│   └── ...
├── data-model.md
├── contracts/
│   └── ...
├── quickstart.md
├── phases/
│   ├── phase-01-{slug}.md
│   ├── phase-02-{slug}.md
│   └── phase-NN-{slug}.md
└── reports/
    └── scout-NN-{area}.md
```

## plan.md Structure

Keep `plan.md` less than or equal to 80 lines, with these sections in order:

1. YAML frontmatter using the closed schema below.
2. `## Context` - links to spec, research reports, brainstorm, related plans.
3. `## Problem` - what is being solved in 1-3 paragraphs.
4. `## Goal` - desired end state in 1 paragraph.
5. `## Scope` - writable and read-only zones.
6. `## Phases` - 5-column table linking each `phases/phase-NN-*.md`.
7. `## Success Metrics` - measurable criteria.
8. `## Key Constraints` - non-negotiables.
9. `## Decisions Made` - table using the format below.
10. `## Unresolved Questions` - omit only when there are none.

## plan.md YAML Frontmatter

The schema is closed. Do not add new top-level fields.

```yaml
---
title: "{Brief title}"
status: todo              # todo | in_progress | done | skipped | blocked | cancelled
priority: P2              # P1 | P2 | P3
effort: 4h                # rough estimate, sum of phase efforts
tags: [frontend, api]
created: YYYY-MM-DD
mode: default             # default | fast | hard
test_mode: none           # none | tdd | ut_backfill
test_target: {}           # ut_backfill only: sub_workspace/module/standalone
scope_mode: hold          # expansion | hold | reduction | skipped
blockedBy: []             # plan dirs that must complete first
blocks: []                # plan dirs blocked by this one
red_team_session: 0       # incremented per /tdk-plan <ID> --red-team run
validation_session: 0     # incremented per /tdk-plan <ID> --validate run
validation_cursor: 0      # next-question index when validate is suspended
schema_version: 3
---
```

Field-write rules:

- `mode`: write `fast` on `--fast`, `hard` on `--hard`. Omit or leave default when no flag was passed. `--red-team` and `--validate` do not change `mode`.
- `test_mode`: write `tdd` on `--tdd`, `ut_backfill` on `--ut-backfill`. Omit or leave `none` when neither test flag was passed. `--red-team` and `--validate` do not change `test_mode`.
- `test_target`: write only when `test_mode: ut_backfill` and at least one targeting flag is present. Shape: `{ sub_workspace: "<name>", module: "<name>", standalone: true }`; omit empty string fields and omit the field entirely for TDD/non-test plans.
- `scope_mode`: written by Step 0.scope. One of `expansion | hold | reduction | skipped`. Absent legacy values are treated as `skipped`.
- `blockedBy` / `blocks`: arrays of plan directory names, or empty arrays when no link exists. The cross-plan dependency scanner gates auto-fix on `schema_version >= 2`.
- `red_team_session` / `validation_session`: monotonic counters; never reset.
- `validation_cursor`: `0` after normal completion; non-zero only when a validation session is suspended mid-interview.
- `schema_version`: bump only for incompatible schema changes.

## Phases Table

Use the 5-column convention:

```markdown
| # | File | Status | Blocks | BlockedBy |
|---|------|--------|--------|-----------|
| 00 | [phase-00-foo](phases/phase-00-foo.md) | todo | 01 | - |
| 01 | [phase-01-bar](phases/phase-01-bar.md) | todo | - | 00 |
```

Status vocabulary: `todo`, `in_progress`, `done`, `skipped`, `blocked`, `cancelled`.

Update phase status with:

1. `(cd "$PROJECT_DIR/.specify/scripts/ts" && bun src/commands/util/update-phase-frontmatter-status.ts "{phasePath}" {status})`
2. `(cd "$PROJECT_DIR/.specify/scripts/ts" && bun src/commands/util/update-phase-status.ts "{FEATURE_DIR}/plan.md" {phaseNumber} {status})`

## Phase File Conventions

Every `phases/phase-NN-*.md` must include, in order:

- YAML frontmatter with `phase`, `title`, `status`, `priority`, `effort`, `dependencies`.
- `## Context Links`
- `## Overview`
- `## Key Insights`
- `## Delegate Skills` when skill routing injects one.
- `## Requirements`
- `## Architecture`
- `## Related Code Files`
- `## Implementation Steps`
- `## Todo List`
- `## Success Criteria`
- `## Risk Assessment`
- `## Security Considerations`
- `## Next Steps`
- `## Unresolved Questions`

File names use `phases/phase-NN-kebab-case-slug.md`: lowercase, hyphen-separated, descriptive.

### Test Mode Sections

When `test_mode: tdd`, phase files replace the generic `## Implementation Steps` execution order with tests-first sections, in order: `## Tests Before`, `## Refactor / Implementation`, `## Tests After`, `## Regression Gate`.

Both `## Tests Before` and `## Tests After` must contain this table:

```markdown
| ID | Source | Scenario | Technique | Input | Expected | Command | Status |
|---|---|---|---|---|---|---|---|
```

`## Tests Before` uses `Status` values `expected_fail`, `characterization`, or `existing_pass`. `## Tests After` must reuse every before-test ID and may add IDs for new behavior. The `## Regression Gate` section must list the command(s) required before the phase can be marked done.

When `test_mode: ut_backfill`, phase files add `## Code Summary`, `## Mocks & Fixtures Required`, and `## Test Matrix` before `## Delegate Skills`.

Backfill phases must satisfy traceability before write:
- each public export / route / method in `## Code Summary` has at least one `## Test Matrix` row;
- each non-trivial branch has a `Branch L<n>` row or `N/A: <reason>`;
- each external dependency has a `Deps` row or `N/A: <reason>`;
- each row has a semantic test ID and leaves `Impl` empty for `/tdk-implement` to fill.

All test-mode phases must apply the Test Case Completeness Rubric from `references/design-phase.md`: Happy, EP, BVA, Branch L<n>, Error, Deps, State, Regression. Do not omit a non-applicable dimension silently; write `N/A: <reason>`.

See `references/design-phase.md` Test Mode Phase Generation for section content rules.

## Quality Checklist

- [ ] All phases have success criteria.
- [ ] File paths are specific and complete.
- [ ] Dependencies are documented with `blockedBy` / `blocks` where applicable.
- [ ] Security concerns are addressed.
- [ ] Test-mode phases apply the completeness rubric and record `N/A: <reason>` for non-applicable dimensions.
- [ ] Backfill `Code Summary` public surfaces are traceable to `Test Matrix` rows.
- [ ] TDD `Tests After` reuses every `Tests Before` ID before adding new behavior cases.
- [ ] Unresolved questions are listed at the end, if any.
- [ ] Reference DAG is acyclic; reference files do not load `SKILL.md`.

## Decisions Made

Every plan that involves a non-trivial technical choice must include:

| Decision | Chosen | Alternatives | Rationale |
|----------|--------|--------------|-----------|
| [Topic] | [Choice] | [Alt1], [Alt2] | [YAGNI / KISS / DRY reasoning] |

## Output Sanitization

- Escape pipe characters (`|`) inside markdown table cells as `\|`.
- Use marker pattern `S{session}.F{N}` for red-team and validation findings.
- Apply the same sanitization rules before writing generated plan content, review findings, or validation notes.
